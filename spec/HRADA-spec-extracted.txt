1. What HRADA Is — Full Context 
An AI Workforce Intelligence platform for growing Thai SMEs (20–500 employees).  Tagline: Put the Right Person in the Right Job and Grow the Right Skills.  Core product loop: 
 RECRUIT → MATCH → DEVELOP → TRACK → new data feeds back into RECRUIT  Find the right person → Fit them to the right work → Grow the right skills → Track the growth  The problem HRADA solves: most organizations aren't short on talented people — they don't 
know what the people they already have are good at, or how to use them well. That information 
is scattered across resumes, HR databases, performance reviews, training records, project 
records, and manager assessments. 
 The core of the system is the Employee Skill Graph — instead of storing an employee as 
just "Marketing Executive," HRADA builds a full capability picture per person: 
 Employee  ├── Skills (individual skills, each with a level)  ├── Experience  ├── Projects  ├── Performance  ├── Learning  ├── Career Goal  └── Workload / Availability  Non-negotiable principle across the entire system: HRADA is a Decision-Support System, 
not an AI that decides for humans. Logic must always be: 
Analyze → Recommend → 
Explain → Human Decides
, never 
Analyze → Decide
. No feature may auto-reject or 
auto-decide anything about a person. Every recommendation must be explainable — this is 
about Fairness, Bias, Explainability, Trust, and Responsible AI. 
 Four user roles:  1. HR / HR Manager — Recruit, Employee Management, Skill Analysis, Learning, 
Tracking, Workforce Analytics 
2. Manager / Project Lead — Create Projects, Find Teams, View team member skills, 
Request AI Recommendations 
3. Employee — View own skills, own Skill Gap, own Learning Path, own Career 
Development 
4. CEO / Business Owner — Workforce Health, Org-wide Skill Gaps, Talent overview, 
Workforce overview 
 Three Talent Classifications:  - Core Expert — deep expertise in one specific skill/domain - Bridge Member — connects skills or people across multiple teams/domains - Developing Talent — still has skill gaps but shows clear potential  What the prototype must make obvious within a few minutes:  Before HRADA — "We have talented people, but we don't really know what each of 
them is good at, or how best to use them." After HRADA — "We can see exactly 
what skills each person has, what role fits them, what they're missing, and how they 
should grow."

3.3 Design Principles to Follow 
- Spend your boldness in one place: the Skill Constellation on the Dashboard is the 
hero moment of the whole system. Everything else stays quiet and disciplined. 
- Avoid generic templated patterns: identical border-radius/shadow on every card 
regardless of hierarchy, all-caps eyebrow labels above every heading, numbered 
markers (01/02/03) that don't represent a real sequence, a "→" appended to every 
button. 
- Motion must be purposeful, not decorative. Use it in exactly two situations: (a) 
responding to a user action (open, expand, confirm, filter), and (b) one orchestrated 
moment on the Dashboard's first load. Not fade-slide-up on every section by default. 
- UI copy (buttons, empty states, errors) uses active voice describing exactly what will 
happen. Action names stay identical through the whole flow (a "Schedule Interview" 
button produces a "Interview scheduled" toast).

Hardcode a Number

10.1 
calcSkillGap(employee, targetRole)
 
gap = max(0, requiredLevel − currentLevel)
, sorted descending, with a 
primaryGap
 field. 
10.2 
calcCandidateMatchScore(candidate, job)
 
Weighted to 100: Required Skills 50% (
avg(min(candidateLevel/requiredLevel, 1))
) 
+ Preferred Skills 15% (same formula) + Experience 15% (
min(years/minExperience, 1)
) 
+ Project Relevance 10% (share of projects touching a required skill) + Assessment 10% 
(
assessmentScore/100
). Always return the total score plus a per-category breakdown. 
Flag 
hasCriticalGap: true
 if any required skill is more than 1.0 below the bar. 
10.3 
calcTeamFit(employee, project)
 
Skill Contribution 50% + Availability 20% (
(100−workload)/100
) + Performance 15% 
(
performance/5
) + Project History 15%. 
10.4 
selectTeam(project, employees, teamSize)
 — 
greedy coverage 
Never just take the top-N highest scores.  
1. uncovered = all of the project's required skills  2. Loop until the team is full or uncovered is empty:     - Count how many uncovered skills each candidate could satisfy (level ≥ required)     - Pick whoever covers the most; break ties by higher teamFit     - Remove the skills they cover from uncovered  3. Fill any remaining slots with highest teamFit among people with availability > 20%  4. If team size ≥ 4, at least one member must be a Developing Talent —     if none qualify, swap out the lowest-fit member for the best-fit Developing Talent and explain 
why in the UI 
 5. If a selected member has workload > 90%, show a Workload Risk warning with a backup 
name 
 6. Return teamGaps = skills the team still doesn't meet, and this must link forward into creating 
a Job 
 Note: with this dataset, the AI Marketing Campaign project will always leave an AI Tools gap — 
make sure it links to the Recruit screen. 
10.5 
classifyTalent(employee)
 
Never hardcode "top 30% = Core Expert."  - Core Expert — has ≥1 skill at level ≥ 4.3 and ≥2 evidence sources for that skill and 
performance ≥ 4.0 
- Bridge Member — has skills ≥ 3.2 spread across ≥3 different categories or ≥2 
cross-department projects 
- Developing Talent — still has a gap toward their target role and average growth from 
history ≥ +0.15/month 
 If someone qualifies for multiple, pick whichever they score highest on, and always return a 
reason. 
10.6 
calcPromotionReadiness(employee)
 
(% of target role's required skills already met × 0.7) + 
(performance/5 × 0.2) + (min(years in current role/3, 1) × 0.1)
 
10.7 
calcWorkforceHealth(employees)
 
Skill Coverage %, Critical Skill Gaps (fewer than 2 people meet the bar), High Potential 
(readiness ≥ 75%), At-Risk Skills (exactly 1 person meets the bar), Workload Risk (workload > 
85% and performance ≥ 4.0), Internal Mobility. 
10.8 
generateLearningPath(employee, catalog)
 
From the primary gap → select matching catalog items by targetSkill, ordered easiest to hardest 
→ always finish with Real Project + Manager Assessment (learning-in-the-flow-of-work 
principle; explain this in the UI).
